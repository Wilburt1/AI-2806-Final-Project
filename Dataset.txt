Challenges (Dimensionality)

The increase in data volume manifests into a number of challenges 

Data imbalance is typical in real data 
Def.: Data imbalance occurs when the distribution of classes in a dataset is not uniform, meaning one class significantly outnumbers the others.
Consequence: Data imbalance could lead to biased models that perform well on the majority class but poorly on the minority class.
Examples: 
-
Medical Diagnosis: healthy versus non-healthy population in the dataset 

-
Fraud Detection: fraudulent transactions might make up only 0.1% of the dataset, while legitimate transactions make up the remaining 99.9%.

-
Image Recognition: a dataset may contain 85% images of cats and only 15% images of dogs 




Variance and Bias: 
The goal of training any model is to generalize towards unseen samples related to a task of interest. Generalization error can be broken into a variance and bias component. 
Bias is the difference between the average prediction of a model and the correct value trying to be predicted. High bias trends towards simplifying the model while not fitting optimally towards the training data. 
Variance refers to the spread of model predictions for a given data point. High variance models tend to perform well on training data, but do not generalize to unseen test data. 
Oftentimes, bias and variance exhibit an inversely proportional relationship which is known as the bias-variance trade off.

Based on a high-degree polynomial → complex model that fits every data point known ➔ difficult to fit to a new data point, thus, high variance

Greedy Algorithms 

Definition

▪
Many optimization problems can be solved more quickly using a greedy approach•
The basic principle is that local optimal decisions may may be used to build an optimal solution

•
But the greedy approach may not always lead to an optimal solution overall for all problems

•
The key is knowing which problems will work with  this approach and which will not







❑
Dynamic programming•
We make a choice at each step

•
The choice depends on solutions to subproblems

•
Bottom-up solution, from smaller to larger subproblems





❑
Greedy algorithm•
Make the greedy choice and THEN

•
Solve the subproblem arising after the choice is made 

•
The choice we make may depend on previous choices, but not on solutions to subproblems

•
Top-down solution, problems decrease in size

•
Doesn’t always yield an optimal solution

Dijkstra’s Algorithm – Graphs Overview 

•
Queue - Store the vertices in a first-in, first out (FIFO) queue as follows. Put the starting node in a queue first. Dequeue the first element and add all its neighbors to the queue. Continue to explore the oldest unexplored vertices first. Thus the explorations radiate out slowly from the starting vertex. This describes a traversal technique known as breadth-first search.

•
Stack - Store vertices in a last-in, first-out (LIFO) stack. Explore vertices by going along a path, always visiting a new neighbor if one is available, and backing up only if all neighbors are discovered vertices. Thus our explorations quickly move away from start. This is called depth-first search.

Mahalanobis Distance

The Mahalanobis distance can be visualized as the distance of a point from the center of a dataset, onto an ellipse (if there are two variables) whose main direction is that of the data, as illustrated in the figure. 
The ellipse drawn is that of equal Mahalanobis distance, so any point lying on that ellipse will be equally far from the centroid. 
The axes of the ellipse are scaled so that they are both of the same length for points at equal Mahalanobis distance from the center.

Information-based Measures

•
The more certain an outcome, the less information that it contains and vice-versa•
For example, if a coin has two heads, then an outcome of heads provides no information




•
More quantitatively, the information is related to the probability of an outcome•
The smaller the probability of an outcome, the more information it provides and vice-versa







… a measure of how much information one set of values provides about another, given that the values come in pairs, e.g., height and weight. 
•
If the two sets of values are independent, i.e., the value of one tells us nothing about the other, then their mutual information is 0.

Coding and Decoding for a Computer  

•
Electrical signals are then translated into universal format (0s,1s), this is known as coding.

•
After processing, output devices transform back data into their original form, this is known as decoding





•
A bit is the smallest unit of data that the computer deals with.•
a bit can take two values (0 or 1).




•
In computer memory data are stored as blocks of bits (bit-patterns), the length of bit-patterns is the number of bits in the bit-patterns.•
A bit-pattern of 8 bits length is called a byte






Data 

Bit Stream 

For Text, 
•
Written text is made of alphabetical symbols (letters). For example, in English there are 26 uppercase and 26 lowercase symbols.

•
Each of those symbols is represented by distinctive bit-pattern (code)

•
Once alphabetical symbols are represented by a bit-pattern, any word that is made of combination of letters can be represented.  





•
The number of possible bit-patterns (symbols) made of N number of bits, M is given by:


                                           M = 2N 
•
Inversely, the number of bits needed to construct M number of symbols is given by: 


                        N= Log2 M ≈ 3.2 Log10 M 
    (Note: N must be rounded to next bigger integer)
•
Ex: for M = 26, what is the min number of bits?


    N= Log2 26 = 3.2 Log10 26 = 4.5 = 5 bits

We can achieve this via a predefined model, e.g., Fourier Transform, DFT, Wavelets … etc. 

•
Or we can use data-centric models such as Autoencoders, CNNs, Transformers, LLMs ... etc. 




•
Representing the data in a different domain is usually motivated by the processing needs

Knowledge and Reasoning

•
The main component in the cycle isKnowledge Representation and Reasoningwhich shows the human-like intelligence in the machines. Knowledge representation is all about understanding intelligence. Instead of trying to understand or build brains from the bottom up, its goal is to understand and build intelligent behavior from the top-down and focus on what an agent needs to know in order to behave intelligently. Also, it defines how automated reasoning procedures can make this knowledge available as needed.





Deductive Reasoning – Making specific conclusions from a general set of facts and logical premises.  If the premises are true, then the conclusions will deterministically be true.

Reasoning

Deductive Reasoning

•
Examples of Deductive Reasoning


Example:
1.
First premise: All men are mortal

2.
Second Premise: Martin is a man

3.
Conclusion: Therefore, Martin is mortal


Example in AI: Rule-Based / Expert Systems – such as decision trees. 


Monotonic Reasoning – 
Holding certain conclusions that do not change regardless of new information being added.  Deductive reasoning is a type of Monotonic Reasoning.

Reasoning

Monotonic Reasoning

Examples of Monotonic Reasoning
Example 1: 
We conclude the earth revolves around the sun.  No matter what other information we learn about the earth or the sun, the initial conclusion of the earth revolving around the sun does not change.
Examples in AI: 
Recommendation systems – Recommender systems collect user rankings and assume that the collection of additional rankings does not change previous rankings.
Malware detection – Malware can be represented as only a small percentage of content in an effort to fool an algorithm to accept it as harmless.  A monotonic malware detector will ignore the extent of benign information and deny access based on any presence of malware regardless of how small.


•
Self-driving cars operate in complex and dynamic environments that require adaptation and decision beyond the rigidness of monotonic reasoning.

•
Monotonic reasoning ignores additional data in favor of adhering to the rule while non-monotonic reasoning allows adaptation based on new scenarios.

•
Example: Emergency Vehicle Approaching•
Monotonic reasoning: If the traffic light is red, stop.

•
Non-Monotonic reasoning: If an emergency vehicle is approaching, yield and clear the way even if the light is red.




•
Example: Unexpected Obstacle•
Monotonic reasoning: Maintain lane position

•
Non-monotonic reasoning: If an object suddenly appears (e.g., fallen tree) break lane position to avoid collision




•
Example: Ethical Dilemma – Choosing to save passengers or a pedestrian•
Monotonic reasoning not equipped to handle potential ethical complexities

•
Non-monotonic reasoning allows for use of context-dependent choices (even if they are can’t be judged as “right” or “wrong”)

Inductive Reasoning – Making general conclusions from a set of specific observations.  The conclusion will be associated with a probability or likelihood of truth and not deterministically true.

Inductive Reasoning

Examples of Inductive Reasoning


Example: A doctor working in an area with a high case of malaria (which always accompanies fever) will infer that a new patient with a fever probably has malaria.  Conversely, a doctor in an area where the observed cases of malaria are rare will infer that a new patient with a fever probably does not have malaria and look for an alternative disease as an explanation.
Example in AI: Machine Learning Models - Machine learning is designed to analyze copious amounts of data in order to build models that can detect and recognize patterns with high probability of accuracy (i.e., image classification, spam filtering, etc.).

Deductive Reasoning

 •
Starts with general principles and applies to specific cases

•
Deals with reasoning towards certain conclusions based on accepted facts and premises



 * Guarantees logical correctness if premises are accurate

 •
Requires accurate premises; false premises lead to false conclusions.

•
Limited applicability to uncertain or incomplete information.



 •
Rule-Based / Expert Systems: These systems use predefined rules to make decisions. For instance, an expert system diagnosing diseases based on symptoms.



 
Inductive Reasoning

 •
Generalizes from specific observations to form broader conclusions.

•
Deals with probability and involves reasoning toward likely conclusions based on data.



 •
Useful for pattern recognition and prediction.

•
Handles uncertainty and incomplete data.



 •
Conclusions are not certain; they are probabilistic.

•
Risk of overgeneralization.



 •
Machine Learning Models: Training models on historical data to predict future outcomes (e.g., predicting stock prices).



 
Abductive Reasoning

 •
Seeks the simplest and most likely explanation for an observation. It is used when data is incomplete or ambiguous.



 •
Useful for hypothesis generation.

•
Handles incomplete information.



 •
Conclusions are speculative; not guaranteed to be true.

•
Requires additional validation.



 •
Natural Language Understanding: Inferring missing context in conversations or understanding ambiguous statements.



 
Monotonic Reasoning

 Monotonic reasoning involves adding new information without retracting previous conclusions. It is used in knowledge representation.

 •
 Simple and straightforward

•
 Supports incremental updates.



 - Cannot handle non-monotonic situations (e.g., exceptions). - May lead to incorrect conclusions when new information contradicts old assumptions.

 •
Malware detection: AI model catches malware even it’s surrounded by mostly benign information.

What is Abductive Reasoning?: The Guide to Guessing Like a Genius!

•
Have you ever played detective and tried to solve a mystery with just a few clues? That’s a bit like what abductive reasoning is all about! It’s a fancy term introduced by a smart thinker named Charles Sanders Peirce from America. Imagine you’re trying to figure out a puzzle, but you don’t have all the pieces. Abductive reasoning helps you make your best guess with the pieces you do have. It’s like being a detective in your own mind, and it’s not just for people; even robots and computers use it to think and solve problems!



Abductive Reasoning 

•
Contrast with Other Reasoning Styles: Abductive reasoning starts with incompletedata, seeking the most likely explanation, unlike deductive reasoning’s general-to-specific approach and inductive reasoning’s specific-to-general pattern.

•
Crucial for Hypothesis Formation: Essential in AI, it facilitates the formation of plausible hypotheses from limited or ambiguous data, a key step in intelligent problem-solving.

•
Integral in Decision-Making: It empowers AI systems to make informed decisions and solve problems efficiently, even when faced with incomplete or uncertain information.

Mean Square Error (MSE): Larger errors are well noted (better than MAE). But the disadvantage is that it also squares up the units of feature as well. 
Root Mean Squared Error (RMSE): Solves the problem of squaring the units.
Mean Absolute Error (MAE): Fails to punish large errors in prediction.

Retain the evaluation scores and discard the model

Average the scores of the model to get a single k-fold validation score

Overview

Terminologies 

Iris flower dataset 



• Samples: A sample is a data item to process (classify).  It can be a document, a picture, audio clip, video, row in database or CSV file, or whatever you can describe with a fixed set of quantitative traits.

• Features: The collection of distinct traits that can be used to describe each data item in a quantitative manner

• Feature Vector:  An n-dimensional vector that contains the concatenation of all features that represent a sample



Overview

Terminologies



• Feature Extraction: A step that transforms the raw data in the high-dimensional space to a space of fewer dimensions (feature vector)

• Learning Model: A class of functions in which an algorithm searches to find one that best estimates the mapping between domain data and target output.  On the implementation level, a model can have either of the following two related meanings: a)
The structure (usually a graph) that expresses the computational process of how a prediction will be computed,

b)
The weights and biases of the computational structure which are determined by learning/training.





• Training Algorithm: The algorithm which trains the model by updating its parameters based on the training dataset to improve its mapping performance.

Clearly, the case of perfect separability is an ideal one. Most "real world" datasets will not have such perfect separability via a linear hyperplane

•
However, if there is no separability then we are unable to construct a MMC by the optimization procedure above. So, how do we create a form of separating hyperplane?

•
Essentially, we must relax the requirement that a separating hyperplane will perfectly separate every training observation on the correct side of the line (i.e. guarantee that it is associated with its true class label), using what is called asoft margin. This motivates the concept of asupport vector classifier(SVC).

Introduction

Types of Learning


Clustering is the unsupervised task of grouping a set of samples in such a way where samples in the same group (called a cluster) are more similar (in some sense) to each other than to those in other groups (clusters).  
•
This implies a need for:

-
Specific features to compare samples

-
Proximity measures to assess the similarity of the samples

-
Clustering algorithms to compute proximity and assigns same labels to similar samples

•
Unlike classification or regression, clustering is an unsupervised learning task since data is unlabeled (no given target labels).

GMM assumes that data points are generated from a mixture of Gaussian distributions, each representing a cluster, with its own mean and covariance.
Expectation-Maximization (EM) Algorithm:
• Expectation (E-Step): Calculate the probability (responsibility) that each data point belongs to each Gaussian component based on the current parameters.
• Maximization (M-Step): Update the parameters (means, covariances, and mixture weights) of the Gaussian components to maximize the likelihood of the observed data.
Iteration: The E-step and M-step are repeated iteratively until convergence, typically when the change in likelihood or parameters falls below a threshold.
Cluster Assignment: Data points are assigned to the Gaussian component to which they have the highest probability of belonging.

Clustering performance evaluation, or cluster validation, is an integral part of the process of developing a clustering model.

•
Not as trivial as counting the number of errors or the precision and recall of a supervised classification algorithm. 

•
An evaluation metric could measure if the results produced by the clustering algorithm: •
Are similar to some ground truth set of classes, or

•
Satisfy some assumption such that members belong to the same class are more similar than members of different classes according to some similarity metric.




•
Ground truth may not always be available to allow for a solid evaluation metric

•
The evaluation metric should be independent of the absolute values of the labels, i.e., a permutation of the class or cluster label values will not change the evaluation scores in any way.



Evaluating Clustering Performance


•Internal Evaluation•
Clustering result is evaluated based on the data that was clustered itself

•
These methods usually assign the best score to the algorithm that produces clusters with high similarity within a cluster and low similarity between clusters.

•
High scores on an internal measure do not necessarily result in effective information retrieval applications

•
Biased towards algorithms that use the same cluster model, i.e. distance based algorithms such as k-means will score high with a distance-based internal evaluation measure.

•
Example measures: Davies-Bouldin Index, Dunn Index, Silhouette Coefficient






Evaluating Clustering Performance

Internal vs External 


•External Evaluation•
Clustering results are evaluated based on data that was not used for clustering, such as known class labels and external benchmarks

•
Such benchmarks consist of a set of pre-classified items, and these sets are often created by (expert) humans.

•
Benchmark sets are referred to as “gold standard” or “ground truth”

•
These evaluation methods measure how close the generated clustering is to the predetermined benchmark classes.

•
Example measures: - Purity - Rand measure





 - F-measure - Jaccard index
 - Dice index - Mutual Information score

Review: Artificial Neural Networks

Common Activation Functions






•
Sigmoids saturate and kill gradients. When the neuron's activation saturates at either tail of 0 or 1, the gradient at these regions is almost zero. Recall that during backpropagation, this (local) gradient will be multiplied to the gradient of this gate's output for the whole objective. Therefore, if the local gradient is very small, it will effectively "kill" the gradient and almost no signal will flow through the neuron to its weights and recursively to its data. Additionally, one must pay extra caution when initializing the weights of sigmoid neurons to prevent saturation. For example, if the initial weights are too large then most neurons would become saturated and the network will barely learn. 



Review: Activation Functions 

Sigmoid and Tanh 

Sigmoid is used for its neuron’s firing and non-firing interpretation 

•
Sigmoid outputs are not zero-centered. This is undesirable since neurons in later layers of processing in a Neural Network would be receiving data that is not zero-centered. This has implications on the dynamics during gradient descent, because if the data coming into a neuron is always positive, then the gradient on the weights will, during backpropagation, become either all positive, or all negative. This could introduce undesirable zig-zagging dynamics in the gradient updates for the weights. However, notice that once these gradients are added up across a batch of data the final update for the weights can have variable signs, somewhat mitigating this issue. Therefore, this is an inconvenience, but it has less severe consequences compared to the saturated activation problem.




Tanh: Like the sigmoid neuron, its activations saturate, but unlike the sigmoid neuron its output is zero-centered. Therefore, in practice the tanh non-linearity is always preferred to the sigmoid nonlinearity. 



•
It was found to greatly accelerate the convergence of stochastic gradient descent compared to the sigmoid/tanh functions. It is argued that this is due to its linear, non-saturating form.

•
Compared to tanh/sigmoid neurons that involve expensive operations (exponentials, etc.), the ReLU can be implemented by simply thresholding a matrix of activations at zero.



Review: Activation Functions 

ReLU

•
Unfortunately, ReLU units can be fragile during training and can "die". For example, a large gradient flowing through a ReLU neuron could cause the weights to update in such a way that the neuron will never activate on any datapoint again. If this happens, then the gradient flowing through the unit will forever be zero from that point on. That is, the ReLU units can irreversibly die during training since they can get knocked off the data manifold. For example, you may find that as much as 40% of your network can be "dead" (i.e. neurons that never activate across the entire training dataset) if the learning rate is set too high. With a proper setting of the learning rate this is less frequently an issue.

•
Leaky ReLU. Leaky ReLUs are one attempt to fix the "dying ReLU" problem. Instead of the function being zero, a leaky ReLU will instead have a small negative slope (of 0.01, or so). Some people report success with this form of activation function, but the results are not always consistent.

Training and Best Practices 


•
There is no one-size-fits-all solution here

•
Use the architecture best suited to the application

•
Broadly speaking, CNN architectures may be divided into two kinds: 1.
Those used for classification

2.
Those used for dense prediction tasks e.g., segmentation, reconstruction … etc.




•
After having determined the application and the corresponding architecture type to use with it, search for baseline models made available to the public by people who worked on the problem before you

•
Some places to look for: GitHub, PyTorch and Tensorflow tutorials … etc.

•
Chances are you will already have a dozen solutions tackling the problem or a similar one; no need to re-invent the wheel!


    
Which Architectures to Use?


•
CNN architectures for classification follow a typical pipeline processing input images via multiple 2D kernels across multiple, stacked layers to result in increasingly smaller activations

•
Output of the last convolution layer unrolled and vectorized, passed to fully connected layers and finally a softmax layer to output pseudo-probabilities for the input belonging to different target classes

•
Size of this logit vector equal to number of target classes

•
Number of kernels should be steadily increased starting from the first convolution layer

•
Experiment with different pooling options 

•
Experiment with different activation functions

•
Experiment with dropout 

•
Experiment with skip connections (e.g., as in Resnet described in earlier lectures)

Classification Architectures

Which Architectures to Use?


•
Many applications require prediction of dense outputs  e.g., image super-resolution, denoising, semantic segmentation etc.

•
Suboptimal to use classification architectures since pooling operations would reduce input resolution and result in deteriorated output quality

•
Hence use fully convolutional architectures 

•
Typically follow an encoder-decoder configuration

•
Encoder similar to a classification type architecture without fully connected layers

•
Decoder works to progressively upsample encoder output to desired output resolution via transposed/deconvolution layers 




See the source image
Dense Prediction Architectures – next 2 lectures

Which Architectures to Use?


•
The choice of the loss function to use with the architecture should be dictated by the nature of the problem

•
For classification tasks, a typical cross-entropy based loss would be the obvious choice

•
For segmentation tasks, the cross-entropy loss would happen on per pixel basis for each pixel of the output

•
For super-resolution, denoising problems, mean square error loss function or L1 loss would be a good choice

•
Special considerations for when there is class imbalance  (more on next slide)



Loss Functions

Which Architectures to Use?


•
Regular cross entropy loss function fails in situations where one of the classes occurs much more frequently than other(s)

•
Observe the picture to the right: the network is much more likely to predict no-fault pixels on the seismic volume compared to fault pixels

•
Same situation with most anomaly, aberrant-event detection problems

•
Regular cross-entropy loss would make the network predict the majority class just by virtue of its overwhelming presence in the training dataset

•
A common occurrence with deep learning models is where they fail to deliver expected performances on training and/or test sets

•
Sometimes, the poor performance might just be a consequence of the hard nature of the problem and indicate more research to be done in designing effective models, capturing better data etc.

•
However, many times, causes of such problems stem from common issues that the practitioner failed to account for earlier

•
Here we look at some of the most common issues that crop up in such situations and some of the ways to tackle them



Model Debugging


•
Model does not have the representational capacity to learn the mapping from input to output data 

•
Typical symptom includes underperformance on both training and test data (situation known as underfitting)

•
Solution is to increase model capacity by increasing the depth of the model, number of learnable kernels etc.

•
Make changes in small steps and monitor test and training performances after each change



Low Model Capacity

Model Debugging


•
When the model has very high representational capacity, it tends to perform well on training data, but poorly on test set—a situation commonly referred to as overfitting

•
Solution is to steadily decrease model capacity (by either reducing the depth and/or the number of learnable kernels) and monitor training and validation error after each change

Transfer Learning from models pretrained on large datasets may also sometimes help

It is known deep networks tend to learn common representations for various tasks in their earlier layers

•
Can be exploited to transfer representations from networks trained on large datasets on one task (i.e., Image Classification on ImageNet) called the source to a different task called the target where quantity of labeled training data is much smaller 

•
Usually done by taking large pretrained network and then finetuning last layer (with all other layers frozen) on target dataset 

•
Helps avoid overfitting and trains a deployable network much faster

•
Pretrained frozen backbone acts as a feature extractor while finetuned last layer acts to project the representations into the decision boundary for the target task

•
Utility depends on how closely related the source and target datasets and/or tasks are
